## Decisions / notes

- **No Node on the host.** All npm/prisma/tsc commands run in `node:22-alpine` via `docker run -u $(id -u):$(id -g) -e HOME=/tmp -v "$PWD":/app -w /app node:22-alpine …`.
- **Migrations are hand-checked.** `0001_init` was generated with `prisma migrate diff --from-empty`, then edited so `searchVector` is `GENERATED ALWAYS AS (...) STORED`. The schema declares it as `Unsupported("tsvector")?`, so the app never writes it. Later migrations: generate a diff and check that it doesn't touch this column.
- **Prisma CLI in the runtime image** comes from a separate `migrator` stage (`/opt/prisma`), because Next's standalone output leaves it out.
- **Backup service** is a custom shell loop rather than `prodrigestivill/postgres-backup-local`, so the 14-dump retention is exact and bind-mount permissions are simple. Dump files are owned by root on the host.
- **Login rate limit** uses one global bucket unless `TRUST_PROXY=true`, since `X-Forwarded-For` can be spoofed when nothing sits in front of the app. Fine for a single user.
- **New env vars beyond the spec:** `COOKIE_SECURE` (set true over HTTPS) and `TRUST_PROXY`.
- **shadcn/ui** components are copied by hand into `components/ui/` (Button, Input/Textarea/Select/Label/Field, Card, Badge, Dialog incl. right-side drawer, Confirm (AlertDialog), EmptyState, PageHeader). Selects are native `<select>` for mobile/a11y.
- **Server actions** live in `lib/actions/*.ts`, take typed objects (validated with zod), and return `ActionResult` (`{ok:true,data?}` or `{ok:false,error,code?}`). They call `revalidatePath("/", "layout")` so the header timer/badges refresh.
- **Datetimes from the browser** are sent as ISO strings (`datetime-local` converted on the client); actions parse with `z.string().datetime({offset:true})`.
- **Board DnD:** the whole column `<section>` is the droppable; collision prefers `pointerWithin` (cards over columns) and falls back to `closestCorners` for keyboard drags. In e2e, wait for dialogs to finish closing before the next drag.
- **Streak:** a day counts when the sum of completed sessions' `durationMin` (grouped by `startedAt` day in TZ) ≥ `minSessionMinutes`. "Sessions this week" counts completed sessions started this week (Mon–Sun in TZ).
- `discardRunningSession` exists in `lib/actions/sessions.ts` but has no UI yet (could go in the stop dialog for sessions started by mistake).
- **E2E:** Playwright runs from `mcr.microsoft.com/playwright:v1.64.1-noble` with `--network host`; see README → Tests.
- **Seed data lives in migrations** (`0002_seed_chaos`), not a seed script: it needs no extra tooling in the runtime image and runs exactly once.
- **Upload body limit:** Next 15.5's middleware buffers request bodies and silently truncates them past 10 MB, so `experimental.middlewareClientMaxBodySize` is set to `1gb` in `next.config.ts` (it's baked in at build time). The real limit is `MAX_UPLOAD_MB`, checked in the upload route (Content-Length first, then per file).
- **No revalidation on note autosave:** `createNote`/`updateNote` don't call `revalidatePath`, because the re-render would remount the editor mid-typing. The pages listing notes are dynamic, so they're fresh on navigation. Use the same pattern for any other autosaving editor.
- **Tags** are normalized to lower-case kebab words (`lib/tags.ts`); `setTags()` builds the Prisma `set` + `connectOrCreate` update.
- **Search markers:** `lib/search.ts` wraps matches in chr(1)/chr(2); render them with `components/search-snippet.tsx` (no HTML). Used by the notes list and global search.
- **Searchable tables** (`Note`, `Postmortem`, `Topic`, `ReadingItem`, `WorkObservation`) have a generated `searchVector`; the import never writes it (Prisma skips `Unsupported` fields).
- **Adding a column or table** means updating `lib/export-format.ts` (schema + `TABLE_LABELS`), `loadExportData()` and `replaceAll()` in `lib/backup.ts` (and `ALL_TABLES`). New optional columns should get a default in the schema so older exports still import; bump `EXPORT_VERSION` only for breaking changes.
- **Charts:** Recharts 3 (`recharts` + its `react-is` peer, pinned). Single-series charts use `var(--chart-1)` (`#2a78d6` light / `#3987e5` dark, from the dataviz reference palette); axis text uses `--muted-foreground`, grid `--border`, tooltips are small app-styled cards, and each chart has an `sr-only` table inside an `sr-only` div (see Step 8). Recharts components must live in client components.
- **Tab/filter strips** (Reading, Work log) are plain `<Link>`s with `aria-current`, so they stay server-rendered.
- **AI:** server-only config in `lib/ai/config.ts` (never import it from a client component); pass `aiEnabled()` down as an `ai` prop. AI server actions go through `run()` in `lib/actions/ai.ts`, streamed answers through `aiRoute()` + `streamText()`.
- **Courses:** items reference resources by the file's id (`resourceKey`); keep that the join key for progress. `templates/` ships in the image (see `.dockerignore`), so edit prompt 1 there and the Courses page picks it up.
- Testing server actions with curl: send multipart (`-F`) with the `$ACTION_REF_1` / `$ACTION_1:0` / `$ACTION_1:1` / `$ACTION_KEY` hidden fields from the page. Action IDs change on every build (see `.next/server/server-reference-manifest.json`).
